# Blackout Widget — дизайн

Дата: 2026-10-17 · Статус: чернетка на погодження

## 1. Навіщо

Зараз користувач кілька разів на день заходить на https://www.dtek-krem.com.ua/ua/shutdowns, вводить місто/вулицю/будинок і передивляється графік, бо ДТЕК його періодично змінює. Хочеться натомість: **один раз ввести адресу, а далі бачити актуальний графік у гарному «скляному» віджеті на робочому столі, який сам оновлюється приблизно кожні 15 хвилин.**

Користувачів двоє: автор і його дівчина. Кожен ставить застосунок собі, у кожного свої налаштування.

**Успіх:** більше не треба відкривати сайт. Одним поглядом на робочий стіл видно: є світло чи ні, коли наступна зміна і графік на сьогодні (і на завтра, якщо опубліковано).

## 2. Цілі, не-цілі, анти-цілі

**Цілі**
- Десктопний застосунок для **Windows і macOS**.
- Одноразове налаштування адреси; дані запам'ятовуються локально.
- Автооновлення графіка ~кожні 15 хв.
- Віджет на робочому столі в стилі glass, **три стилі на вибір**: Компакт, Циферблат, Таймлайн.
- **Розширюваність:** архітектура з окремими «джерелами» (провайдерами) для сайтів різних обленерго. Перше джерело — ДТЕК Київські регіональні електромережі (dtek-krem). Пізніше, наприклад, Волинь з іншим сайтом додається як нове джерело без переписування віджета й налаштувань.

**Не-цілі (у першій версії)**
- Інші регіони, крім dtek-krem (але архітектура під них готова).
- Сповіщення/нагадування про відключення. *(моє рішення — не обговорювали; легко додати пізніше)*
- Підпис коду, нотаризація, магазини застосунків, автооновлення самого застосунку.
- Системні панелі віджетів (Windows Widgets board, macOS WidgetKit).
- Кілька віджетів на столі одночасно.
- Мобільні платформи, англійська мова інтерфейсу.
- Windows 10 і Mac на Intel (цільові машини — Windows 11 і M1).

**Анти-цілі (провал, навіть якщо «технічно працює»)**
- Віджет показує **графік не тієї черги/лінії**. Це гірше, ніж нічого.
- Віджет мовчки показує **застарілі дані як актуальні**.
- Віджет **зникає з робочого столу по Win+D** (користувач явно обрав, що це важливіше за справжнє системне скло).
- Застосунок «довбить» сайт ДТЕК частіше, ніж раз на ~15 хв, або паралельними запитами.

## 3. Що вирішив користувач

- Windows + macOS. Цільові машини: **Windows 11** і **Mac на M1** (Apple Silicon).
- Ввести адресу один раз; автооновлення ~15 хв.
- **Аварійне відключення обов'язково має бути помітно позначене у віджеті** (§7).
- Glass/fluid дизайн; усі три стилі віджета з макетів лишаються, перемикаються.
- Якщо будинок підключений до кількох ліній — окремий крок вибору лінії. Квартира користувача — **Лінія 1**.
- Проєктувати з розрахунком на інші сайти/регіони.
- Лише для двох людей.
- **Віджет не повинен зникати по Win+D** → на Windows прикріплюємо вікно до робочого столу і імітуємо скло (див. §7), замість справжнього Acrylic.
- Погоджено в обговоренні (мої пропозиції, які користувач підтвердив):
  - Electron як технологія; іконка в треї / рядку меню; автозапуск.
  - Якщо сайт недоступний — віджет показує останні дані й час останнього успішного оновлення.
  - Поки що лише dtek-krem.
  - Один віджет одночасно; стиль перемикається в налаштуваннях і через правий клік.
  - Віджет лежить на робочому столі під вікнами, перетягується мишкою, позиція запам'ятовується.
  - Відлік і маркер «зараз» оновлюються щохвилини локально; графік — раз на ~15 хв.
  - Півгодинні клітинки — половинками, як на сайті.
  - Завтра ще не опубліковано → штриховка з підписом «ще не опубліковано».
  - Скло підлаштовується під світлу/темну тему системи.
  - Клік по віджету відкриває головне вікно з повним графіком і налаштуваннями (адреса, лінія, стиль, автозапуск).

## 4. Як працює сайт dtek-krem (перевірено прототипом 2026-10-17)

Зразки відповідей лежать у `docs/superpowers/specs/assets/dtek-krem-samples/`.

### 4.1 Захист
- Сайт за **Imperva (Incapsula)**. Звичайний HTTP-запит отримує 212-байтну заглушку з JS-перевіркою — без браузера даних не дістати.
- **Прихований Electron `BrowserWindow` (`show: false`) з постійною сесією (`partition: 'persist:dtek-krem'`) проходить перевірку.** Перший раз: сторінка сама перезавантажується (перший `loadURL` завершується `ERR_ABORTED` — це очікувано, треба чекати появи даних), кілька секунд. Наступні запуски зі збереженими cookies — ~2 с.

### 4.2 Дані на сторінці `/ua/shutdowns`
Inline-скрипти заповнюють глобальний об'єкт `DisconSchedule`. Увага: він **не** на `window` (`window.DisconSchedule === undefined`), але доступний як `DisconSchedule` у `webContents.executeJavaScript`. Готовність сторінки = `typeof DisconSchedule !== 'undefined' && DisconSchedule.fact`.

| Поле | Що містить |
|---|---|
| `DisconSchedule.streets` | `{ "м. Біла Церква": ["бул. Грушевського Михайла", …], … }` — усі населені пункти (ключі) і їхні вулиці, ~470 КБ. Джерело для підказок міста/вулиці. |
| `DisconSchedule.fact` | Фактичний графік: `{ data: { "<unix ts опівночі за Києвом>": { "GPV1.2": { "1": "yes", …, "24": "yes" }, … } }, update: "17.10.2026 11:55", today: <ts> }`. Ключі `"1".."24"` = проміжки 00–01 … 23–24. Завтра — окремий ключ дня; з'являється, коли ДТЕК опублікує (на момент перевірки був лише сьогоднішній день). |
| `DisconSchedule.preset` | `sch_names` (`"GPV1.2": "Черга 1.2"`), `time_zone` (24 проміжки), `time_type` (тексти легенди для кожного статусу), `days`, а також `data` — **тижневий план «можливих відключень»** по чергах і днях тижня (сайт зараз його не показує: `showTablePlan = false`). |
| `<meta name="csrf-token">` | CSRF-токен для AJAX (параметр `_csrf-dtek-krem`). |

**Статуси годин** (з `preset.time_type`): `yes` — світло є; `no` — світла немає; `first` — не буде перші 30 хв; `second` — не буде другі 30 хв; `maybe` — можливо відключення (сайт малює як «немає»); `mfirst` / `msecond` — можливо не буде перші/другі 30 хв.

### 4.3 Запит адреси (AJAX)
- `POST /ua/ajax`, `application/x-www-form-urlencoded`, заголовки `X-CSRF-Token: <meta csrf-token>`, `X-Requested-With: XMLHttpRequest`. Виконувати **зсередини прихованої сторінки** (`fetch` у `executeJavaScript`) — same-origin, cookies і CSRF уже є.
- Тіло: `method=getHomeNum`, `data[0][name]=city`, `data[0][value]=<місто>`, `data[1][name]=street`, `data[1][value]=<вулиця>`, `data[2][name]=updateFact`, `data[2][value]=<fact.update, який у нас є>`.
- Відповідь: `data: { "<номер будинку>": { sub_type, start_date, end_date, type, sub_type_reason: ["GPV1.2", "GPV4.2"], voluntarily, cek } }`, `updateTimestamp`, прапорці `showCurOutageParam`, `showCurSchedule`, `showTableFact`, … Ключі `data` — список будинків вулиці (джерело для підказок номера будинку; трапляються дивні ключі на кшталт `":0098"`, `"46ПР_142"` — показувати як є).
- **Якщо переданий `updateFact` застарів, відповідь додатково містить свіжі `fact` і `preset`** (перевірено). Отже, регулярне оновлення = **один** такий запит: і черги будинку, і новий графік.
- Не перевірено: що саме приходить у `sub_type` / `type` / `start_date` / `end_date` / `voluntarily` / `cek`, коли для будинку діє аварійне чи екстрене відключення (на момент перевірки поля були порожні). Сайт показує це окремим блоком над графіком.

### 4.4 Як визначається «Лінія N»
Із коду сайту (`discon-schedule.js`, `tableRender`):
```js
presets = key_preset.slice(0, 2);                  // key_preset = sub_type_reason
presets = presets.filter(key =>
  /* є в fact.data для кожного дня */ && DisconSchedule.preset.sch_names[key]);
// "Лінія 1" = presets[0], "Лінія 2" = presets[1]
```
- Лінія N = N-й елемент `sub_type_reason` після відкидання черг, яких немає у `fact.data` чи `preset.sch_names`; **щонайбільше 2 лінії** (будинок 13 має 4 черги, сайт показує лише перші дві).
- Порожній `sub_type_reason` → сайт не показує графік (для будинку немає черги).
- Перевірено на бул. Грушевського Михайла, 40 (м. Біла Церква): `["GPV1.2", "GPV4.2"]` → Лінія 1 = черга 1.2; її `fact` збігся зі скріншотом сайту годину в годину (немає 06:00–08:30 і 15:00–19:00).
- Сайт сам перевіряє оновлення раз на 15 хв (`limitUpdateTime: 15`) — наш інтервал узгоджений.

## 5. Архітектура

**Технологія:** Electron + TypeScript. *(Electron — погоджено; TypeScript, electron-vite, React для UI, electron-builder для збірки — моє рішення)*

```
main process
├── providers/            ScheduleProvider-и (поки: dtek-krem)
│   └── browser-session   спільний помічник: прихований BrowserWindow + persist-partition
├── scheduler             таймер оновлень, backoff, resume/online тригери
├── store                 налаштування + кеш останнього знімка (JSON у userData)
├── widget-window         вікно віджета, прикріплення до столу, імітація скла
├── main-window           налаштування + повний графік
└── tray                  трей / рядок меню
renderer
├── widget                3 стилі
└── app                   майстер налаштування, повний графік, налаштування
```

### 5.1 Інтерфейс джерела
```ts
interface ScheduleProvider {
  id: string;                    // 'dtek-krem'
  displayName: string;           // 'ДТЕК Київські регіональні електромережі'
  listCities(): Promise<string[]>;
  listStreets(city: string): Promise<string[]>;
  listHouses(city: string, street: string): Promise<HouseInfo[]>;
  fetchSnapshot(address: Address): Promise<ScheduleSnapshot>;
}

interface HouseInfo { house: string; lines: LineInfo[] }        // lines: 0, 1 або 2
interface LineInfo  { index: number; groupId: string; label: string } // 1, 'GPV1.2', 'Черга 1.2'
interface Address   { providerId: string; city: string; street: string; house: string; lineIndex: number; groupId: string }
```
Новий регіон = нова папка в `providers/`, що реалізує цей інтерфейс, + реєстрація. Віджет, сховище і UI працюють лише з нормалізованою моделлю. Джерела, яким не потрібен браузер, просто роблять `fetch`.

### 5.2 Нормалізована модель
```ts
type Slot = 'on' | 'off' | 'maybe-off' | 'unknown';
interface DaySchedule { date: string /* YYYY-MM-DD, Europe/Kyiv */; slots: Slot[] /* 48 півгодинок */ }
interface ScheduleSnapshot {
  providerId: string; address: Address;
  groupLabel: string;            // 'Черга 1.2'
  days: DaySchedule[];           // сьогодні + завтра, якщо опубліковано
  sourceUpdatedAt?: string;      // fact.update, напр. '17.10.2026 11:55'
  fetchedAt: string;             // ISO
  lines: LineInfo[];             // поточні лінії будинку — для виявлення змін (§6)
  currentOutage?: { text: string; start?: string; end?: string }; // якщо джерело повідомляє про поточне аварійне/екстрене
}
```
Мапінг dtek-krem (година → 2 півгодинки): `yes`→`[on,on]`, `no`→`[off,off]`, `first`→`[off,on]`, `second`→`[on,off]`, `maybe`→`[maybe-off,maybe-off]`, `mfirst`→`[maybe-off,on]`, `msecond`→`[on,maybe-off]`, невідоме значення → `unknown` (і запис у лог).
*(48 півгодинок на день — моє рішення: це покриває всі відомі графіки України; дні переходу на літній/зимовий час не обробляємо окремо — ДТЕК теж дає рівно 24 години.)*

Тижневий план (`preset.data`) у першій версії не використовуємо, але парсер не повинен на ньому падати.

## 6. Оновлення і стійкість

- **Розклад:** при старті, далі кожні 15 хв (±1 хв випадкового зсуву — моє рішення), а також після виходу зі сну (`powerMonitor 'resume'`), при поверненні мережі та вручну («Оновити зараз»). Ніколи не частіше, ніж раз на 5 хв автоматично; ніяких паралельних запитів до одного джерела.
- **Цикл dtek-krem:** прихована сторінка тримається завантаженою; оновлення = один `getHomeNum` з поточним `updateFact`. Якщо запит падає (не 200, не JSON, CSRF) — перезавантажити сторінку (знову пройти Imperva) і повторити один раз. Тримати сторінку відкритою чи перезавантажувати щоразу — вирішує будівельник.
- **Помилки:** експоненційний backoff до 15 хв. Віджет показує останній знімок, «оновлено о HH:MM» завжди видно; якщо знімок старший за 45 хв — помітний індикатор «дані застаріли». *(45 хв — моє рішення)*
- **Капча:** якщо Imperva вимагає інтерактивної перевірки (немає `DisconSchedule` після ~30 с), застосунок показує в треї та головному вікні кнопку «Пройти перевірку», яка відкриває це приховане вікно користувачу. Cookies зберігаються в partition, далі знову приховано.
- **Зміна схеми будинку:** зберігаємо і `lineIndex`, і `groupId`. Показуємо графік за `lineIndex` (так, як показав би сайт). Якщо під цим індексом тепер інша черга або лінії зникли — віджет показує помітне попередження «Схема підключення змінилась — перевірте лінію» з переходом у налаштування. *(моє рішення)*
- **Кеш:** останній успішний знімок зберігається на диск; після перезапуску без мережі віджет одразу показує його з відповідною позначкою.

## 7. Віджет

**Макети:** `docs/superpowers/specs/assets/2026-10-17-widget-styles.html` (відкрити в браузері; обрані всі три).

- **A. Компакт** (~290×150): стан («Світло є» / «Світла немає» / «Можливе відключення»), відлік до наступної зміни, смужка на сьогодні з маркером «зараз», підпис «Лінія 1 · черга 1.2 · оновлено HH:MM».
- **B. Циферблат** (~236×260): 24-годинне кільце, відключення — дуги, біла точка — «зараз»; у центрі стан і відлік; підпис знизу.
- **C. Таймлайн** (~400×200): стан і відлік зверху; дві смужки «Сьогодні DD.MM» / «Завтра DD.MM»; завтра без даних — штриховка «ще не опубліковано».

Спільне:
- Тексти відліку: «Вимкнення о 15:00 · через 3 год 10 хв»; коли світла немає — «Увімкнуть о 19:00 · через 1 год 5 хв». Якщо в доступних даних змін більше немає — «Без змін до кінця графіка». Відлік перетинає північ, якщо завтрашній графік відомий.
- `maybe-off` має окремий вигляд (наприклад, штрихований бурштин), щоб відрізнявся від певного «немає». *(моє рішення)*
- **Аварійне/екстрене відключення** (вимога користувача — помітно позначати): якщо джерело повідомляє про нього для будинку, у віджеті з'являється окрема помітна позначка (наприклад, червонуватий бейдж «Аварійне» / «Екстрене», інший колір індикатора стану) у всіх трьох стилях. Воно ж **перебиває стан за графіком**: великий статус і відлік перемикаються на нього («Світла немає · аварійне · орієнтовно до 17:00», якщо відомий кінець; інакше без відліку) *(перебивання — моє рішення)*. Іконка в треї теж відображає аварійний стан. Поля, що це несуть, ще не бачили заповненими (§4.3) — парсити обережно, сирі значення логувати; для перевірки UI потрібен тестовий знімок з аварійним станом.
- Відлік і маркер «зараз» оновлюються на межі кожної хвилини.
- **ЛКМ** — відкрити головне вікно; **перетягування** — переміщення (відрізняти від кліку); **ПКМ** — меню: стиль ▸, Оновити зараз, Налаштування, Вийти. Позиція зберігається; якщо монітор зник — повернути на основний.
- Тема — за системною (світла/темна).

### 7.1 Прикріплення до столу і скло — Windows (частково перевірено)
- Прототип: безрамкове прозоре вікно, `SetParent(hwnd, Progman)` після `SendMessageTimeout(Progman, 0x052C, 0xD, 0x1, …)` через FFI (koffi) → **вікно лишається видимим після Win+D і лежить під іншими вікнами** (перевірено на Windows 11 build 26300).
- Ціна: дочірнє вікно **втрачає системний Acrylic** (у прототипі текст просто на шпалерах). Тому скло імітуємо: застосунок читає поточні шпалери (шлях і режим розміщення: fill/fit/stretch/tile/center/span; на кожному моніторі свої), вирізає ділянку саме під віджетом, розмиває й малює як фон + тонування + світлий бордюр, як у макетах. Перемальовувати при переміщенні, зміні шпалер, зміні моніторів/DPI. Однотонний фон — тривіальний випадок.
- Запасний варіант, якщо шпалери не прочитати (слайдшоу, Windows Spotlight тощо): напівпрозора тонована підкладка без розмиття.
- **Не перевірено, перевірити першим:** чи прикріплене вікно отримує клік / перетягування / ПКМ; поведінка при кількох моніторах і різному DPI (координати дочірнього вікна відносно Progman); перезапуск `explorer.exe` (Progman перестворюється → треба виявити, напр. через повідомлення `TaskbarCreated`, і прикріпити знову).

### 7.2 Прикріплення і скло — macOS (не перевірено, Mac'а не було)
- `type: 'desktop'` в Electron **не підходить як основний шлях**: за документацією таке вікно не отримує фокус, клавіатуру й події миші.
- Основний шлях (не перевірено): звичайне безрамкове вікно з `vibrancy` (нативне скло macOS розмиває шпалери саме), а через FFI (koffi + Objective-C runtime, `objc_msgSend` на NSWindow з `getNativeWindowHandle()`) — рівень вікна трохи вище за іконки столу (`kCGDesktopIconWindowLevel + 1`) і `collectionBehavior` = `canJoinAllSpaces | stationary` (stationary — вікно не зсувається при «Показати робочий стіл» / Mission Control).
- Перевіряти на Mac M1: видимість при «Показати робочий стіл», перемикання просторів, клік/перетягування/ПКМ.
- Якщо вікно на такому рівні не реагує на мишку — див. §7.3.

### 7.3 Якщо «на столі» і «клікабельний» конфліктують
*(моє рішення — користувач цю розвилку не обрав; спирається на його вибір «не зникати по Win+D» понад справжнє скло)*
- Пріоритет — **віджет лишається на столі**. Якщо на якійсь системі прикріплений віджет не отримує подій миші, він стає лише для перегляду, а все керування переходить у трей / рядок меню: «Показати графік», «Стиль ▸», «Оновити зараз», і **режим «Перемістити віджет»** (тимчасово відкріплює вікно, дозволяє перетягнути, потім прикріплює знову).
- Клікабельність прикріпленого віджета — бажана, пробуємо, але не блокує реліз.

## 8. Головне вікно

- **Майстер першого запуску:** Регіон/компанія (поки один пункт, але крок є — *моє рішення*) → Місто (автодоповнення з `streets`) → Вулиця → Будинок (з `getHomeNum`) → Лінія (лише якщо ліній дві; показати графік на сьогодні для кожної лінії поруч, щоб легко звірити із сайтом) → Стиль віджета → Готово.
- **Повний графік:** вкладки «Сьогодні / Завтра», 24-годинна сітка з половинками, як на сайті; «оновлено о» (наш час отримання) і «графік ДТЕК від» (`sourceUpdatedAt`); повідомлення про поточне відключення, якщо є.
- **Налаштування:** змінити адресу/лінію, стиль віджета, автозапуск (за замовчуванням увімкнено — *моє рішення*), «Оновити зараз».
- Головне вікно — звичайне вікно, тож може використовувати справжній Acrylic/vibrancy.

## 10. Збірка і встановлення

- electron-builder: Windows 11 — NSIS `.exe` (x64); macOS — `.dmg` лише **arm64** (M1).
- Без Developer ID і нотаризації. На Apple Silicon потрібен щонайменше **ad-hoc підпис** (інакше застосунок не запуститься) — перевірити, що збірка його має.
- README з інструкцією першого запуску: Windows SmartScreen («Докладніше → Виконати все одно»); macOS — у нових версіях «ПКМ → Відкрити» вже не обходить Gatekeeper, тож: Системні параметри → Конфіденційність і безпека → «Все одно відкрити», або `xattr -cr /Applications/<App>.app`.
- koffi (FFI) потрібен на обох ОС (Windows — прикріплення до столу; macOS — рівень вікна, §7.2), різний код за платформою.
- macOS-збірку з цієї Windows-машини не зробити. *(моє рішення, бо доступ до Mac для збірки не підтверджено)*: приватний GitHub-репозиторій + GitHub Actions з macOS-раннером (arm64) збирає `.dmg`; перевірку робить власник Mac за чек-листом з §11/§12. Windows-збірку можна робити локально або тим самим CI. Тому macOS — окрема віха після Windows: спершу прототип §7.2 на Mac (через CI-збірку + перевірку власником), потім решта.

## 11. Тестування

- Модульні тести: парсер dtek-krem на зразках з `assets/dtek-krem-samples/` (розбір `fact`, мапінг статусів у півгодинки, визначення ліній з `slice(0,2)` + фільтр); обчислення «наступної зміни» (через північ, без завтрашніх даних, коли змін немає); логіка застарілості; виявлення зміни схеми будинку.
- Ручна перевірка: Win+D, перезапуск explorer.exe, сон/пробудження, офлайн, зміна шпалер, кілька моніторів.

## 12. Ризики (перевірити на початку)

1. Взаємодія з прикріпленим вікном на Windows (клік, перетягування, ПКМ).
2. Імітація скла через шпалери: режими розміщення, кілька моніторів, Spotlight/слайдшоу.
3. macOS: вікно рівня столу + vibrancy + взаємодія — повністю не перевірено.
4. Imperva посилить захист (капча) — є план у §6.
5. ДТЕК змінить розмітку сайту — парсер ізольований у провайдері; віджет показує останні дані + помилку.

## 15. Питання без відповіді (вирішено за замовчуванням, користувач може змінити)

1. Чи є доступ до Mac для збірки/тестів — не підтверджено → CI-збірка + перевірка власником (§10).
